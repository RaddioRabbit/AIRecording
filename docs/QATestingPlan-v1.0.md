## 1. 测试策略总览

### 1.1 测试金字塔

```
        /\
       /  \     E2E 测试（10%）— 验证完整用户流程
      /____\
     /      \   集成测试（30%）— 验证模块间协作
    /________\
   /          \ 单元测试（60%）— 验证核心逻辑
  /____________\
```

### 1.2 测试类型定义

| 测试类型 | 目标 | 覆盖范围 | 执行时机 |
|----------|------|----------|----------|
| **单元测试** | 验证最小可测试单元的正确性 | 业务逻辑、工具函数、数据转换 | 每次代码提交前（pre-commit） |
| **集成测试** | 验证模块间接口和数据流 | 录音→存储、转录→纪要、历史→搜索 | 每次 PR 合并前（CI） |
| **E2E 测试** | 验证完整用户场景 | 端到端用户操作流程 | 每日构建 + 发布前 |
| **性能测试** | 验证性能指标达标 | 冷启动、转录速度、内存占用 | 每周回归 + 发布前 |
| **安全测试** | 验证隐私和安全约束 | 数据不上传、加密存储、权限 | 发布前必做 |
| **兼容性测试** | 验证多环境兼容性 | macOS 版本 × 硬件架构 | 发布前必做 |

### 1.3 测试环境矩阵

| 环境 | 用途 | 配置 |
|------|------|------|
| 开发环境 | 开发自测 | 开发者本地 Mac |
| CI 环境 | 自动化测试 | GitHub Actions / GitLab CI + macOS Runner |
| 测试环境 | QA 手工测试 | 专用测试机（Intel + Apple Silicon 各 1 台） |
| 预发布环境 | 发布前验证 | 与生产环境一致配置 |

## 3. 性能测试方案

### 3.1 性能测试指标与验证方法

| 性能指标 | 目标值 | 测试方法 | 测试工具 | 通过标准 |
|----------|--------|----------|----------|----------|
| 应用冷启动时间 | < 3 秒 | 从点击应用到主窗口完全加载 | Xcode Instruments / 手动计时 | 连续 10 次测试，平均值 < 3s，最大值 < 5s |
| 录音启动延迟 | < 500ms | 从点击"开始录音"到实际录音开始 | 日志时间戳差值 | 连续 20 次测试，平均值 < 500ms，最大值 < 800ms |
| 中文识别准确率 | >= 90% | 使用标准测试集（安静环境） | 自定义脚本对比 ground truth | 字错误率（CER）<= 10% |
| 转录速度 | >= 0.5x 实时 | 1 小时录音，记录转录耗时 | 日志时间戳 | 转录耗时 <= 30 分钟 |
| 纪要生成时间 | < 1 分钟（1 小时录音） | 记录从转录完成到纪要生成完成 | 日志时间戳 | 连续 5 次测试，平均值 < 1 分钟 |
| 内存占用（空闲） | < 200MB | 应用启动后静置 1 分钟 | Xcode Instruments - Allocations | 峰值 < 200MB |
| 内存占用（转录中） | < 1GB | 执行 1 小时录音的转录任务 | Xcode Instruments - Allocations | 峰值 < 1GB |
| CPU 占用（录音中） | < 10%（M1） | 录音过程中监测 CPU | Activity Monitor / top | 平均值 < 10% |
| 1 小时录音文件大小 | < 500MB | 录制 1 小时音频，检查文件大小 | 文件系统 API | 文件大小 < 500MB |

## 5. 隐私与安全测试

### 5.1 隐私测试方案

| 测试项 | 验证目标 | 测试方法 | 通过标准 |
|--------|----------|----------|----------|
| 原始音频不上传 | 确保音频文件不离开本地 | 网络抓包（Charles / Wireshark） | 未捕获到音频文件上传请求 |
| 脱敏文本上传 | 验证仅上传文本 | 网络抓包 + 内容审查 | 上传内容为文本，不含音频数据 |
| 本地加密存储 | 验证加密功能有效 | 检查存储文件 + 尝试解密 | 加密文件无法直接播放，正确密码可解密 |
| 数据清除功能 | 验证清除彻底性 | 执行数据清除，检查文件系统 | 所有录音、转录、纪要数据被删除 |
| 离线功能可用 | 验证无网络时基础功能 | 断开网络，测试录音+转录 | 录音和本地转录正常工作 |

### 5.2 安全测试用例

| 用例编号 | 用例名称 | 测试步骤 | 预期结果 |
|----------|----------|----------|----------|
| SEC-001 | 音频文件不上传验证 | 1. 开启网络抓包<br>2. 完成录音、转录、纪要生成全流程<br>3. 分析所有网络请求 | 无任何请求包含音频文件数据 |
| SEC-002 | 传输加密验证 | 1. 开启网络抓包<br>2. 触发云端 AI 调用<br>3. 检查请求协议 | 所有请求使用 HTTPS（TLS 1.3） |
| SEC-003 | 本地存储加密 | 1. 开启加密存储<br>2. 完成录音<br>3. 尝试直接播放存储文件 | 文件无法直接播放，需解密 |
| SEC-004 | 数据清除彻底性 | 1. 录制多条录音<br>2. 执行"清除所有数据"<br>3. 检查存储目录和数据库 | 所有相关文件被删除，数据库记录清空 |
| SEC-005 | 权限最小化 | 1. 检查应用请求的权限列表<br>2. 验证每项权限的必要性 | 仅请求必要的权限（麦克风、系统音频） |
| SEC-006 | 崩溃后数据不泄露 | 1. 录音过程中强制终止应用<br>2. 检查临时文件 | 临时音频文件不暴露敏感信息 |

## 8. Bug 严重程度分级

### 8.1 分级定义

| 级别 | 定义 | 示例 | 响应时间 | 修复期限 |
|------|------|------|----------|----------|
| **P0 - 致命** | 导致应用崩溃、数据丢失、核心功能完全不可用 | 录音过程中崩溃导致文件丢失；无法启动应用；隐私数据泄露 | 2 小时内响应 | 24 小时内修复 |
| **P1 - 严重** | 核心功能受损，有规避方案但体验差 | 转录准确率低于 80%；纪要生成失败；内存泄漏导致卡顿 | 4 小时内响应 | 3 天内修复 |
| **P2 - 一般** | 非核心功能缺陷，不影响主流程 | 搜索响应稍慢；UI 显示错位；快捷键冲突 | 1 天内响应 | 1 周内修复 |
| **P3 - 轻微** | 体验优化项，几乎不影响使用 | 文字排版不美观；提示文案不友好；深色模式颜色偏差 | 2 天内响应 | 下个版本修复 |

### 8.2 Bug 流转状态

```
新建 → 确认 → 分配 → 修复中 → 待验证 → 已验证 → 关闭
          ↓
        拒绝/重复/延期
```
