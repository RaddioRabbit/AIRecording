## 1. 风险总览

本文档识别并评估 AI 录音助手（macOS 桌面端）项目在开发、测试和发布阶段面临的各类风险。风险按技术、隐私合规、性能和项目四个维度分类，每项风险包含概率、影响、缓解措施和责任人。

## 2. 技术风险

### 2.1 风险清单

|------|----------|----------|------|------|----------|----------|--------|
| T-001 | 本地转录引擎准确率不达标 | 本地 Whisper 或 Apple Speech 在中文场景下识别准确率无法达到 >= 90% 的目标，尤其在口音、噪音环境下表现差 | 中 | 高 | **高** | 1. M3 早期进行转录引擎选型 POC，对比多种引擎准确率<br>2. 准备标准中文测试集，量化评估<br>3. 保留云端转录作为降级方案<br>4. 针对常见口音和噪音场景做模型微调 | claude-cp-arch |
| T-002 | 说话人分离准确率不足 | 本地模型在 2-4 人场景下说话人分离准确率低于 80%，导致纪要质量下降 | 高 | 高 | **高** | 1. 评估专用说话人分离库（pyannote、resemblyzer）<br>2. 允许用户手动修正说话人标识<br>3. 提供"不分离说话人"的降级选项<br>4. 收集用户反馈持续优化模型 | claude-cp-arch |
| T-003 | 系统音频捕获技术障碍 | macOS 系统音频捕获需要特殊权限或驱动（如 BlackHole），用户配置复杂，体验差 | 中 | 高 | **高** | 1. 调研 ScreenCaptureKit / Core Audio 原生方案<br>2. 提供一键安装音频驱动的引导流程<br>3. 默认推荐麦克风录制，系统音频作为高级选项<br>4. 准备详细的用户文档和故障排查指南 | claude-cp-arch |

| T-005 | 本地转录性能不足 | 长录音（>1 小时）在低端 Mac 上转录速度低于 0.5x 实时，用户等待时间过长 | 中 | 中 | **中** | 1. 支持 Apple Silicon Neural Engine 加速<br>2. 实现转录任务后台执行，允许用户继续使用应用<br>3. 提供转录进度和预计完成时间<br>4. 对 Intel Mac 提供性能基准测试和最低配置要求 | claude-cp-arch |
| T-006 | 数据模型兼容性 | 后续版本数据模型变更导致旧版本录音/转录数据无法读取 | 低 | 高 | **中** | 1. 设计可扩展的数据模型，预留字段<br>2. 实现数据库迁移机制（Core Data Migration / SQL 迁移脚本）<br>3. 版本升级前自动备份数据<br>4. 发布前进行升级兼容性测试 | claude-cp-arch |
| T-007 | 音频文件损坏或丢失 | 录音过程中应用崩溃或系统异常导致音频文件损坏，无法恢复 | 中 | 高 | **高** | 1. 实现分段写入机制，定期 flush 到磁盘<br>2. 录音过程中维护写入日志<br>3. 应用崩溃后自动检测和恢复未完成的录音<br>4. 提供录音文件完整性校验 | claude-cp-dev |
| T-008 | 内存泄漏导致应用崩溃 | 长时间运行或反复录音转录后出现内存泄漏，导致应用卡顿或崩溃 | 中 | 中 | **中** | 1. 使用 Instruments 定期检测内存泄漏<br>2. 对长录音和重复操作场景做压力测试<br>3. 实现内存使用监控和告警<br>4. 关键操作后主动释放大对象 | claude-cp-dev |

## 7. Top 5 风险优先级排序

基于风险等级、概率和影响的综合评估，以下是需要最高优先级关注和资源投入的前 5 项风险：

### Top 1：说话人分离准确率不足（T-002）

| 维度 | 评估 |
|------|------|
| 风险等级 | 高 |
| 概率 | 高 |
| 影响 | 高 |
| 优先级理由 | 说话人分离是产品差异化核心功能，直接影响纪要质量。本地实现技术难度高，且当前开源方案在中文场景下表现不稳定。 |
| 建议行动 | 1. M3 第一周完成说话人分离 POC<br>2. 准备 3 套备选方案（专用库/云端/手动标注）<br>3. 若本地方案不达标，评估云端分离或允许用户手动修正 |

### Top 2：本地转录引擎准确率不达标（T-001）

| 维度 | 评估 |
|------|------|
| 风险等级 | 高 |
| 概率 | 中 |
| 影响 | 高 |
| 优先级理由 | 转录准确率是产品基础，低于 90% 将严重影响用户体验和产品口碑。中文语音识别在口音、噪音环境下挑战大。 |
| 建议行动 | 1. M3 早期完成转录引擎选型对比测试<br>2. 建立标准中文测试集并量化评估<br>3. 保留云端转录作为准确率不达标的降级方案 |

### Top 3：用户隐私顾虑导致 adoption 低（PROJ-007）

| 维度 | 评估 |
|------|------|
| 风险等级 | 高 |
| 概率 | 中 |
| 影响 | 高 |
| 优先级理由 | 录音软件天然涉及敏感数据，用户对隐私高度敏感。一旦产生隐私信任危机，将直接影响用户获取和留存。 |
| 建议行动 | 1. 产品设计阶段将隐私作为核心卖点<br>2. 提供完全离线模式<br>3. 官网和产品内透明展示数据处理流程<br>4. 考虑开源核心隐私相关代码 |

### Top 4：原始音频意外上传（P-001）

| 维度 | 评估 |
|------|------|
| 风险等级 | 高 |
| 概率 | 低 |
| 影响 | 高 |
| 优先级理由 | 虽然概率低，但一旦发生将造成不可逆的隐私事故，严重损害品牌信誉，可能面临法律风险。 |
| 建议行动 | 1. 网络层强制拦截音频文件上传<br>2. 每次发布前进行网络抓包审计<br>3. 代码审查时将网络请求作为重点检查项<br>4. 建立发布检查清单（Checklist） |

### Top 5：系统音频捕获技术障碍（T-003）

| 维度 | 评估 |
|------|------|
| 风险等级 | 高 |
| 概率 | 中 |
| 影响 | 高 |
| 优先级理由 | 系统音频录制是核心 P0 功能，但 macOS 对系统音频捕获限制严格，技术实现复杂，用户体验可能不佳。 |
| 建议行动 | 1. M2 期间完成系统音频捕获技术预研<br>2. 调研 ScreenCaptureKit 等原生方案<br>3. 设计优雅的用户引导流程<br>4. 准备系统音频不可用的降级方案 |

## 8. 风险跟踪与治理

### 8.1 风险跟踪机制

| 活动 | 频率 | 参与人 | 输出 |
|------|------|--------|------|
| 风险识别会 | 每两周 | 核心团队 | 更新风险清单 |
| 风险评审会 | 每月 | 核心团队 + CEO | 风险状态报告 |
| 风险应急演练 | 每季度 | QA + 开发 | 应急响应流程验证 |

### 8.2 风险状态定义

| 状态 | 定义 |
|------|------|
| 已识别 | 风险已记录，尚未制定缓解措施 |
| 缓解中 | 缓解措施正在实施 |
| 已缓解 | 缓解措施已实施，风险等级降低 |
| 已接受 | 团队决定接受风险，不采取额外措施 |
| 已触发 | 风险已发生，进入应急响应 |
| 已关闭 | 风险已解决或不再适用 |

### 8.3 风险升级路径

```
风险发现

                  |

                  |
```
