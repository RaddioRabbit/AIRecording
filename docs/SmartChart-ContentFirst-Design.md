# SmartChart 内容优先智能图表设计

## 文档信息

| 项目 | 内容 |
|---|---|
| 产品 | AIRecording |
| 功能 | 录音详情中的智能图表 |
| 状态 | 已确认设计 |
| 日期 | 2026-07-16 |
| 替代方向 | 取代当前“先判断录音类型，再套固定图表模板”的选图方式 |

## 1. 背景与问题

当前智能图表虽然可以输出思维导图、流程图、时间线等形式，但图中经常只有“主题”“要点”“待办”等泛化内容，不能明显降低用户理解录音的成本。

根本问题不是图表模板数量不足，而是处理顺序错误：系统先决定图表形式，再要求内容适应模板。录音中真正有价值的可能是方案对比、原因与结果、观点分歧、事件变化、任务依赖或一组关键数字，而不一定符合“会议、访谈、讲座”等预设类型。

本设计将 SmartChart 重新定义为：

> LLM 根据录音内容中实际存在的数据、结构和关系，自动路由到一种最合适的图表；如果没有合适图表，则在一张重点句子卡片中展示全部重点原话。

## 2. 设计目标

### 2.1 核心目标

1. 一段录音只生成一个最合适的图表。
2. 图表选择依据内容中真实存在的关系和数据，而不是录音所属场景。
3. 图表中的每项事实、数字、节点和关系都可以定位到原始录音片段。
4. 没有足够结构时不强行画图，自动降级为一张重点句子卡片。
5. 用户无需选择图表类型，也无需通过追问才能获得默认结果。

### 2.2 非目标

本次设计不包含：

- 同时生成多张候选图表供用户选择。
- 由用户手动选择饼图、流程图、思维导图等形式。
- 在默认界面中提供连续追问或聊天功能。
- 复杂的证据侧栏、图表评分面板或路由解释面板。
- 让 LLM 直接生成任意 HTML、CSS 或 JavaScript。
- 图表节点拖拽、编辑和协作功能。

## 3. 已确认的产品原则

### 3.1 内容优先

系统不再首先判断“这是会议还是访谈”，而是判断录音中是否存在适合可视化的内容结构，例如：

- 多个对象在共同维度上的差异；
- 事件之间的时间顺序；
- 人物、概念或观点之间的关系；
- 原因、结果和影响链路；
- 流程步骤、条件和分支；
- 行动、负责人、时间和依赖；
- 可以直接比较的数值。

### 3.2 一次只展示一个结果

LLM 只选择一种最有助于理解当前录音的展示方式。系统不在页面上同时堆叠多张图表，也不让用户承担选图责任。

### 3.3 可以不画图

当录音只有零散但重要的表达，没有稳定关系或可比较数据时，系统不生成形式化图表，而是显示一张“重点句子”卡片。

卡片内部展示所有被识别为重点的句子，不设置固定条数上限，并按录音时间顺序排列。

### 3.4 所有内容可追溯

每个用户可见的事实性图表元素必须绑定至少一个转录片段 ID。点击该元素时，App 从对应时间点播放录音。

LLM 可以压缩措辞，但不能补充录音中不存在的事实、数字、人物立场或因果关系。

## 4. 用户体验

### 4.1 默认流程

1. 用户打开一条已有转录的录音。
2. 用户点击“生成图表”。
3. 系统分析完整转录，并由 LLM 选择最合适的图表。
4. 页面展示一个标题和一张图表。
5. 用户点击图表中的内容，可跳转到对应录音时间点。
6. 用户可以点击“重新生成”重新分析。

生成图表不再依赖 AI 纪要。已有 AI 纪要可以作为辅助上下文，但不能替代原始转录，也不能成为事实来源。

### 4.2 页面结构

智能图表区域只包含：

- 图表标题；
- 图表类型的简短名称；
- 一张图表或一张重点句子卡片；
- “重新生成”按钮；
- 加载、失败和重试状态。

页面不显示图表候选列表、评分过程、复杂路由理由、追问输入框或独立证据面板。

### 4.3 图表点击行为

图表节点、数据点、关系线和重点句子都携带 `segmentIds`。用户点击后：

1. 选择最早的来源片段作为播放起点；
2. 将播放器定位到该片段的 `startTime`；
3. 开始播放或等待用户点击播放，遵循当前播放器既有交互；
4. 同时在转录区域定位并短暂突出对应段落。

## 5. 图表路由能力

LLM 从允许列表中选择一种 `visualizationKind`。路由依据是内容结构，不是录音类型。

| 类型 | 标识 | 进入条件 | 展示重点 |
|---|---|---|---|
| 对比图 | `comparison` | 至少两个对象，且存在至少两个共同比较维度 | 差异、优劣、代价和共同点 |
| 时间线 | `timeline` | 存在有意义的事件顺序、阶段或状态变化 | 关键事件和转折，不罗列所有时间词 |
| 关系图 | `relationship` | 人物、概念、观点之间存在明确的命名关系 | 谁提出什么、概念如何关联、观点如何支持或反对 |
| 因果/流程图 | `flow` | 存在明确的因果链、操作顺序、条件或分支 | 原因、步骤、条件、结果和后果 |
| 决策/行动图 | `action` | 存在决策、任务、负责人、截止时间或依赖关系 | 决定了什么、谁负责、下一步和阻塞项 |
| 数值图 | `quantitative` | 存在同单位、可比较的真实数值序列 | 数值差异、趋势或构成 |
| 重点句子卡片 | `highlights` | 其他图表均不满足进入条件 | 全部重点原话，按时间顺序展示 |

`quantitative` 的具体表现形式由数据形态决定：

- 不同类别的单值比较使用柱状图；
- 同一指标随时间变化使用折线图；
- 构成数据有明确整体且各部分可验证时才使用饼图或环形图。

思维导图不再作为默认兜底。只有录音中确实存在稳定的层级包含关系时，才可由 `relationship` 渲染器使用树状布局。

## 6. LLM 分析与路由

### 6.1 输入

LLM 接收带来源信息的转录片段，而不是只有 AI 纪要的 Markdown：

```json
{
  "recordingId": "recording-id",
  "segments": [
    {
      "id": "segment-id",
      "speaker": "说话人",
      "startTime": 965.2,
      "endTime": 972.8,
      "text": "方案 B 的准确率高了 12%，但交付会晚两周。"
    }
  ]
}
```

### 6.2 长录音处理

当完整转录超过模型的安全上下文预算时，服务按转录片段边界拆分，不截断句子。

处理分为两步：

1. 每个分块提取候选事实、数字、事件、关系和重点原话，并保留来源片段 ID。
2. 全局路由器读取去重后的候选目录，选择一种图表并生成最终图表计划。

分块阶段不生成普通摘要，避免摘要格式再次影响图表结构。

### 6.3 严格输出

LLM 只输出符合 JSON Schema 的 `ChartPlan`，不输出 HTML：

```json
{
  "visualizationKind": "comparison",
  "title": "两个技术方案的权衡",
  "routingConfidence": 0.88,
  "items": [
    {
      "id": "item-1",
      "label": "准确率提高 12%",
      "role": "benefit",
      "segmentIds": ["segment-id"]
    }
  ],
  "relations": [],
  "series": [],
  "highlightSentences": []
}
```

字段规则：

- `visualizationKind` 必须来自允许列表；
- `title` 可以概括内容，但不能加入新事实；
- 每个 `item`、`relation` 和数值数据点必须包含 `segmentIds`；
- 数值同时保存原始文本和解析后的数值；
- `routingConfidence` 表示这种图表是否适合表达当前录音，不表示转录准确率。

## 7. 验证与降级

LLM 选择图表后，系统必须验证计划。验证通过前不进行渲染。

### 7.1 通用验证

- `visualizationKind` 在允许列表中；
- 所有来源片段 ID 均存在；
- 每个事实性元素至少绑定一个来源片段；
- 引用原话可以在对应片段中找到；
- 去除重复或近义重复的节点；
- `routingConfidence` 不低于 0.70；
- 图表至少包含两个有区分度的内容单元。

### 7.2 类型验证

- 对比图：至少两个比较对象、两个共同维度；
- 时间线：至少三个有顺序意义的事件或阶段；
- 关系图：至少两条有来源证据的明确关系；
- 因果/流程图：每条因果或条件关系都能在原文中找到语言依据；
- 决策/行动图：任务、负责人、时间和依赖只展示原文明确出现的字段；
- 数值图：所有可视数值 100% 与原文匹配，单位一致或已进行可验证转换。

任一关键验证失败时，不尝试用另一种形式包装同一批不可靠数据，直接降级为 `highlights`。

### 7.3 重点句子卡片

重点句子卡片是一个容器，内部列出全部重点句子。它不是多张独立卡片。

每条句子包含：

- 原始句子；
- 说话人；
- 开始和结束时间；
- 重点标签，例如“关键判断”“重要数据”“风险”“未解决问题”“行动承诺”；
- 对应转录片段 ID。

句子按录音时间顺序排列。系统去除寒暄、口头填充、同义重复和脱离上下文会产生误解的截断句，但不对最终重点句子数量设置固定上限。

## 8. 渲染机制

LLM 输出的是内容计划，渲染由确定性组件负责。

每个渲染器只处理一种语义结构：

- `ComparisonRenderer`
- `TimelineRenderer`
- `RelationshipRenderer`
- `FlowRenderer`
- `ActionRenderer`
- `QuantitativeRenderer`
- `HighlightsRenderer`

渲染器负责：

- 布局；
- 节点和连线；
- 文本截断与展开；
- 主题颜色；
- 鼠标和键盘交互；
- 将点击事件中的 `segmentIds` 发送给 Swift。

LLM 不得提供 CSS 类名、坐标、HTML 片段或脚本，以避免样式漂移、安全风险和不可验证输出。

## 9. 服务数据流

```text
转录片段
  -> 分块候选提取（长录音时）
  -> 候选合并与去重
  -> LLM 图表路由与 ChartPlan 生成
  -> Schema 校验
  -> 来源证据校验
  -> 类型适配校验
  -> 固定渲染器生成 HTML
  -> WKWebView 展示
  -> 点击元素跳转录音时间点
```

建议将当前 ChartAgent 图调整为：

```text
prepare_transcript
  -> extract_candidates
  -> route_and_plan
  -> validate_plan
  -> render_chart
  -> validate_render
```

不再保留 `content_type_detect -> CHART_STRATEGY_MAP` 作为主路由路径。

## 10. 错误处理

| 场景 | 行为 |
|---|---|
| 没有完整转录 | 显示“请先完成转录”，不调用图表服务 |
| 转录内容过短且没有重点句子 | 显示“内容不足，暂时无法生成图表” |
| LLM 输出不符合 Schema | 使用纠错提示重试一次 |
| 重试后仍无效 | 使用可验证候选生成重点句子卡片 |
| 图表计划验证失败 | 降级为重点句子卡片 |
| 重点句子也无法可靠提取 | 明确显示生成失败，不制造内容 |
| 本地图表服务未启动 | 尝试启动；失败后显示重试按钮 |
| 用户点击失效的来源片段 | 不跳转，记录错误并保持当前播放状态 |

## 11. 当前代码改造范围

### 11.1 Swift 端

- `RecordingDetailViewModel.generateChart()`：移除“必须先生成 AI 纪要”的限制，发送转录分段及时间信息；
- `ChartSkill.swift`：用新的 `ChartPlan`、来源引用和图表类型替换当前通用节点模型；
- `RecordingDetailView.swift`：保持单图表界面，加入图表元素到播放器的跳转；
- `ChartWebView.swift`：接收 WebView 消息并回传 `segmentIds`；
- `HTTPChartSkill.swift`：适配新请求和响应版本。

### 11.2 Python ChartAgent

- `main.py`：接收转录分段数组，而不是只有纪要字段；
- `graph.py`：替换现有内容类型检测和固定策略路由；
- `nodes.py`：实现候选提取、LLM 路由、计划校验和降级；
- `templates.py`：改为按 `visualizationKind` 注册确定性渲染器；
- 增加 JSON Schema 和各图表类型验证器。

### 11.3 不在本次改造范围

- 不修改录音、转录和 AI 纪要的生成流程；
- 不重构与智能图表无关的页面；
- 不添加云端图表存储或分享功能；
- 不引入用户自定义图表主题。

## 12. 测试设计

### 12.1 单元测试

- ChartPlan JSON 解码与非法字段拒绝；
- 每种图表类型的进入条件；
- 来源片段存在性和引用匹配；
- 数值、单位和百分比校验；
- 重复节点去除；
- 低置信度降级；
- 重点句子排序、去重和完整保留；
- WebView 点击消息到播放器时间点的映射。

### 12.2 集成测试

测试样本按内容关系覆盖，而不是只按录音场景覆盖：

- 有明确方案权衡的录音；
- 有阶段和转折的录音；
- 有人物或概念关系的录音；
- 有因果链和条件分支的录音；
- 有任务、责任和依赖的录音；
- 有真实数值对比或趋势的录音；
- 只有零散重点句子的录音；
- 内容短、含混、重复或转录质量较差的录音；
- 超出单次模型上下文的长录音。

### 12.3 验收标准

1. 每次生成最多返回一个图表或一个重点句子卡片。
2. 用户不需要选择图表类型。
3. 100% 的事实性图表元素都包含有效来源片段 ID。
4. 100% 的可视数值都可以在来源片段中找到，并保留单位。
5. 不满足图表进入条件的样本全部降级为一张重点句子卡片。
6. 重点句子卡片展示全部通过筛选的重点句子，不设置固定数量上限。
7. 点击任意可交互图表元素，可以定位到正确录音时间点。
8. 人工评审中，至少 80% 的测试样本被认为“图表形式与内容匹配”。
9. 人工评审中，至少 80% 的测试样本被认为“查看图表比直接阅读完整转录更容易理解核心内容”。
10. 严重事实编造和无来源数字的数量为 0。

## 13. 实施顺序建议

1. 定义转录分段请求、ChartPlan Schema 和验证规则；
2. 实现重点句子卡片，建立可靠降级路径；
3. 实现 LLM 路由和来源校验；
4. 依次实现对比、时间线、关系、流程、行动和数值渲染器；
5. 接通图表元素到录音播放位置的跳转；
6. 建立关系型测试集和人工评审流程；
7. 移除旧的内容类型策略映射和未接通的伪图表类型。

## 14. 最终产品定义

SmartChart 不再追求“把每段录音画成某种图”，而是：

> 让 LLM 判断哪一种图表最能压缩和解释当前录音，并用可追溯的原始内容填充它；如果图表不能带来理解收益，就把全部重点原话清晰地放在一张卡片中。
