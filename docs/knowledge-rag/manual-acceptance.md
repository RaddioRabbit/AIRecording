# 录音知识库 RAG 手工验收

本清单仅在自动化测试全部通过后执行。全程不要把 `.env` 内容、录音标题、转写文本、会议纪要、问题或回答粘贴到终端或问题追踪工具中。

1. 运行 `git check-ignore -v .env`，确认 `.env` 被忽略；打开本地 `.env` 时只确认存在允许的键名 `DASHSCOPE_API_KEY`，不要显示其值。
2. 启动应用，打开“知识库”，等待历史已完成录音的索引进度结束。
3. 选择两条已知录音，提出一个答案必须跨越这两条录音才能得出的提问。
4. 确认回答的每个事实性段落都显示来源引用芯片；没有证据的提问必须显示“知识库中没有足够依据。”
5. 点击每一个来源芯片，确认对应录音打开，播放器跳转到引用时间且原始转写高亮正确片段。
6. 在本地安全地移除 `DASHSCOPE_API_KEY` 后重启知识库服务，确认界面显示 FTS 降级提示，且仍可完成基于关键词的查询。
7. 恢复密钥后点击重试缺失嵌入，确认降级提示消失或待处理嵌入数量减少。
8. 软删除一条已被引用的录音，确认它不再出现在新的检索结果；历史来源芯片显示为不可用而不是打开已删除录音。
9. 在不录音时终止 KnowledgeAgent，确认应用自动恢复知识库服务；录音和本地转写流程不被中断。
10. 检查 `~/Library/Logs/AIRecording/app.log` 与 `knowledge-agent.log`：只允许出现事件、状态、计数、耗时和脱敏的记录 ID；不得出现密钥值、Bearer token、录音标题、说话人、片段文本、问题、回答、转写或会议纪要。
