# 智能图表：完整长图 PNG 导出修复设计

- 日期：2026-07-25
- 状态：设计已确认，待实施
- 范围：macOS App 的智能图表 PNG 导出

## 1. 问题

智能图表较长时，当前 PNG 导出结果虽然具有长页面尺寸，但只绘制了
`ChartWebView` 可视框内的图表内容。框外节点没有出现在图片中，底部留下大块空白。

当前导出器读取 `document.documentElement.scrollWidth` 和 `scrollHeight`，并将该尺寸交给
`WKSnapshotConfiguration.rect`。但是配置较大的快照区域不会自动扩大 `WKWebView` 的实际渲染表面，
因此 WebKit 仍可能只绘制当前视口。

工作区已有一处未提交尝试：快照前临时把 `WKWebView` 的 frame 调整为页面内容尺寸。
该方向与根因一致，但还需要等待 WebKit 完成重新布局、处理布局后的最终尺寸，并完整恢复用户现场。

## 2. 目标与验收标准

导出的 PNG 必须：

1. 包含整个智能图表内容：标题、内容类型、摘要框和完整思维导图。
2. 保持当前图表区域的导出宽度，只向下扩展高度。
3. 不缩小文字，不裁切可视框之外的节点。
4. 图片底部紧随实际页面内容，不出现因视口截断造成的大块空白。
5. 导出前后的预览尺寸、缩放比例和滚动位置一致。
6. 如果导出失败，不写出残缺图片，并向用户显示“导出失败，请重试”。

本次不修改思维导图内容、节点上限、视觉样式、编辑方式、缩放功能或默认文件名。

## 3. 方案比较

### 方案 A：临时扩大当前 WebView（采用）

快照前测量完整页面尺寸，临时扩大当前 `WKWebView`，等待 WebKit 重新布局，再按最终内容尺寸截图。
无论成功或失败，都恢复原始尺寸、缩放和滚动位置。

优点：

- 直接修复当前视口裁切根因。
- 复用已加载完成的页面，不需要重复加载 HTML。
- 改动集中，符合现有架构。

代价：

- 必须可靠地等待重新布局。
- 必须确保所有退出路径都恢复用户现场。

### 方案 B：使用离屏 WebView 导出

创建一个隐藏的 `WKWebView`，加载同一份 HTML，按完整内容尺寸渲染后截图。

优点是完全隔离屏幕上的预览；缺点是需要复制页面配置、等待加载、管理生命周期，
容易产生预览与导出内容不同步的问题，超出本次修复所需范围。

### 方案 C：完整页面 PDF 转 PNG

先生成完整 PDF，再栅格化为 PNG。该方案能保留矢量清晰度，但流程和内存管理更复杂，
还可能带来页面尺寸、背景色或缩放差异，不适合本次单一裁切问题。

## 4. 导出流程

导出操作按以下顺序执行：

1. 冲刷尚未完成的思维导图编辑渲染，确保预览对应最新大纲。
2. 保存 `WKWebView` 的原始 frame、magnification 和滚动位置。
3. 将导出缩放设为 100%，避免用户预览缩放影响原图。
4. 读取页面当前完整宽高。
5. 保持当前导出宽度，将 `WKWebView` 临时调整到完整内容高度。
6. 等待 WebKit 完成一次重新布局和绘制。
7. 再次测量页面最终宽高，以吸收尺寸变化造成的排版调整。
8. 如最终高度变化，再调整一次并等待布局稳定。
9. 使用稳定后的完整页面 rect 创建快照。
10. 恢复原始 frame、magnification 和滚动位置。
11. 将快照转换为 PNG；用户确认保存位置后，以原子写入方式落盘。

现场恢复必须覆盖成功、快照失败、PNG 转换失败和用户取消保存等全部退出路径。
用户取消保存不是错误，不显示失败提示。

## 5. 组件边界

### `MindMapPNGExporter`

负责：

- 测量页面内容尺寸。
- 临时调整 `WKWebView`。
- 等待 WebKit 重新布局。
- 获取完整页面快照。
- 恢复 WebView 现场。
- 将 `NSImage` 转换为 PNG 数据。

该组件不负责保存面板、录音信息或 UI 错误文案。

### `RecordingDetailViewModel`

继续负责：

- 冲刷待渲染编辑。
- 调用完整页面导出器。
- 打开 `NSSavePanel`。
- 写入 PNG。
- 记录成功或失败日志并更新用户可见错误。

### 不修改的组件

- `ChartWebView`：继续负责预览加载、缩放和节点点击。
- Python `MindMapRenderer`：已经输出包含全部节点的完整 SVG，不参与本次修复。
- 智能图表 DTO、持久化和编辑模型：数据契约不变。

## 6. 错误处理与资源限制

- 页面尺寸无效、JavaScript 测量失败、WebKit 快照失败或 PNG 编码失败时，中止保存。
- 使用作用域清理保证 WebView 现场恢复，恢复逻辑不依赖导出成功。
- 导出继续使用当前支持的思维导图规模上限；本次不增加节点数量，因此不新增图片分片或超大图片降级机制。
- 日志只记录稳定事件名和错误类型，不记录标题、图表内容或完整文件路径。

## 7. 测试策略

### 自动测试

1. 创建高度明显大于 WebView 可视框的测试 HTML。
2. 在页面底部放置颜色明确的标记区。
3. 使用较小 frame 的真实 `WKWebView` 执行完整页面快照。
4. 断言导出图片高度覆盖完整页面。
5. 检查图片底部标记区像素，证明框外内容被实际绘制，而不只是生成了空白长画布。
6. 断言成功导出后 frame、magnification 和滚动位置恢复。
7. 构造失败路径，断言现场同样恢复且不产生 PNG。
8. 保留现有 PNG 数据、文件写入和文件名测试。

### 人工验收

使用能够生成两到三屏高度的真实思维导图：

- 导出图片包含标题、类型、摘要和最后一个思维导图节点。
- 图片宽度与当前图表区域一致。
- 文字大小正常，无节点裁切。
- 最后一个节点之后只有正常页面边距，没有异常大块空白。
- 导出后 App 中的缩放比例和滚动位置没有跳动。
